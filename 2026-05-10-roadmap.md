# tmux-agent-deck Product Roadmap

**Date:** 2026-05-10
**Status:** Approved

## Context

The MVP is complete and working: a TUI for managing AI coding agent sessions in tmux with status detection, hierarchical groups, a ctrl+q return-to-TUI flow, split-panel detail/output/notes, and the M1 interaction primitives. This roadmap now starts at the next unfinished phase.

**Core product job:** See what every agent is doing, get to the ones that need you fast, control the fleet without leaving the terminal.

---

## Current State

- ✅ **MVP** — session list, status detection, groups, attach/detach, SQLite
- ✅ **Return-to-TUI** — ctrl+q detach keybinding
- ✅ **Split panel TUI** — detail panel, live output, notes, pane list
- ✅ **M1 Interaction Primitives** — send, fork, broadcast, pane targeting, improved bash status heuristics
- ✅ **M3 Conductors + macOS Alerts** — conductor ownership, escalation, digests, notification styles, quiet hours
- ✅ **M5 Fleet Management** — multi-select, bulk ops, archive/restore, tags
- ✅ **M6 Polish + Onboarding** — filter, help overlay, empty-state onboarding, configurable poll, headless mode
- ✅ **M2 Finish Observability** — context window indicator, waiting timer/fleet bar color polish
- ✅ **M4 Session Configuration** — project path picker, tool selection, group defaults, startup scripts
- ✅ **Auto-Escalation** — `--auto-escalate` flag; poller sends escalation message to conductor on `→ waiting` transition
- 🔧 **Tool Flags** — `tool_flags` DB column (schema v6); 5-step new-session dialog; `claude-dangerous` preset works; free-text flags broken (BUG-013 open)

## Milestone 1 — Interaction Primitives
**Theme: Close the input loop so you can respond to agents without attaching**

Features shown in existing mockup footer (`x Send`, `f Fork`) — implement the missing half of the UI.

| Feature | Key | Description | Effort |
|---|---|---|---|
| Send to pane | `x` | Inline prompt; sends typed text via `tmux send-keys` to selected session; returns to TUI immediately | S |
| Fork session | `f` | Clone selected session's `ProjectPath`, `Tool`, `GroupPath` into new session; prompt for new title | S |
| Broadcast to group | `b` | Send same keys to every running session in cursor's group — useful for `/compact`, `ctrl+c` | M |
| Pane targeting | `tab` | Cycle active pane in the detail panel; `x` sends to that pane specifically | S |
| Improved status heuristics | — | Extend `DetectStatus` with per-tool patterns (Copilot, Aider, raw bash PS1) beyond Claude's `>` prompt | M |

**Key files:** `internal/ui/dialog.go` (reuse `dialogState` for send prompt), `internal/tmux/client.go` (add `SendKeys`), `internal/tmux/status.go` (extend `DetectStatus`)

**Sequencing:** Split panel TUI surfaces pane info and output — the natural next step is acting on what you see. Fork reuses existing session creation path. Send is a 1-day add-on.

**Status:** Complete. Remaining validation is mostly manual QA around attach return flow, real tool prompts, and a few terminal interaction edges.

## Milestone 3 — Conductors and macOS Alerts
**Theme: Route waiting work to one operator without spamming Notification Center**

| Feature | Key | Description | Effort |
|---|---|---|---|
| Group conductor session | `c` | Mark one session in a group as its conductor; render it distinctly and use it as the default escalation target | S |
| Escalate to conductor | `C` | From a waiting session, send a templated handoff with source title and current issue context to the group's conductor | S |
| Waiting summary digest | — | Send a short conductor-facing summary of all waiting child sessions in a group instead of separate alerts | M |
| macOS notification tuning | `--notify-style` | Preserve `--notify` opt-in, then choose `waiting`, `conductor`, or `digest` routing for alerts | M |
| Quiet hours / debounce | `--notify-quiet` | Suppress repeated alerts during configured quiet windows or cooldown periods | M |

**Key files:** `internal/ui/app.go` (conductor assignment, escalation flow), `internal/ui/dialog.go` (handoff UX), `internal/state/poller.go` (waiting digest + notification routing), `internal/notify/notify.go` (macOS notification policy)

**Sequencing:** Conductor ownership comes first because escalation, digesting, and notification routing all depend on a stable target. Minimal escalation comes next, then notification styles, and quiet-hour/debounce policy lands last once the event flow is in place.

## Milestone 4 — Session Configuration
**Theme: Launch the right agent in the right context without typing it all out**

| Feature | Key | Description | Effort |
|---|---|---|---|
| Project path picker | `n` flow | During session creation, second prompt pre-filled with cwd; supports `~` and `$VAR` expansion | S |
| Tool selection | `n` flow | After project path, cycle available tools (`claude`, `aider`, `cursor`, bash, custom) with arrow keys | S |
| Group defaults | — | Wire up existing `default_tool` / `default_path` group columns — new sessions in a group inherit as pre-filled prompts | S |
| Startup script | — | Add `startup_script TEXT` column; send to pane 2s post-creation — lets you auto-send `claude --resume` | M |
| Session presets | — | Named presets in `~/.config/tmux-agent-deck/presets.toml`; `n` shows preset picker before manual flow | L |

**Key files:** `internal/ui/dialog.go` (multi-step `new-session` flow), `internal/db/db.go` (schema v5: add `startup_script` column), `internal/db/groups.go` (read `default_tool`/`default_path`)

**Schema state:** Current schema is v4. `startup_script` does not exist yet — it needs to be added as a v5 migration to the `sessions` table and `Session` struct. `default_tool` and `default_path` columns already exist in the `groups` table — wiring them up is UI work only.

**New-session dialog state:** Currently single-step (title only), hardcodes `ProjectPath: "."` and `Tool: "claude"`. All M4 UI work starts here.

**Sequencing:** Path and tool selection improve every new session immediately. Group defaults cost ~1 day (schema already there). Startup scripts require a schema migration (v5) before the send-on-start logic. Presets are deferred — need a config format decision.

## Milestone 5 — Fleet Management
**Theme: Operate 20+ agents without losing track**

| Feature | Key | Description | Effort |
|---|---|---|---|
| Multi-select | `space` | Toggle selection mark on cursor item; footer shows `[3 selected]` counter | M |
| Bulk kill / bulk move | `d` / `m` | With selection active, kill or move all selected sessions at once | S |
| Bulk send | `x` | `x` with selection active sends same keys to all selected running sessions | S |
| Archive / restore | `a` / `A` | Move session to `archived/` group, mark stopped; hidden from default list; toggle `A` to view archived | M |
| Tags / labels | `t` | Add `tags TEXT` to DB; tag editor on `t`; filter list by tag prefix in search (`#backend`) | L |

**Key files:** `internal/ui/app.go` (selection + bulk action state), `internal/ui/list.go` (selection rendering and archived/tag filtering), `internal/db/sessions.go` (archive/tag persistence helpers)

**Sequencing:** Multi-select unlocks all bulk ops and should land first. Archive/restore is a small schema change reusing group mechanics. Tags are last because they touch DB, rendering, and search behavior.

## Milestone 6 — Polish and Onboarding
**Theme: Make the first 10 minutes and the 1000th session equally smooth**

| Feature | Key | Description | Effort |
|---|---|---|---|
| Session list search / filter | `/` | Live prefix-filter of session titles in left panel; non-matching sessions hidden; empty groups auto-collapse | M |
| Keyboard shortcut help | `?` | Full-screen overlay listing all keybindings grouped by context; dismiss with `q` or `?` | S |
| Empty-state onboarding | — | When DB has no sessions, detail panel shows quickstart: "Press n to create your first session" | S |
| Configurable poll interval | `--poll` | CLI flag to set poller interval (`--poll 500ms`, `--poll 2s`) | S |
| Headless / daemon mode | `--headless` | Run poller + notifications without TUI; useful for background monitoring | L |

**Key files:** `internal/ui/list.go` (filter predicate in `BuildTree`), `internal/ui/app.go` (filter + help state), `cmd/root.go` (poll interval flag), `internal/state/poller.go` (configurable ticker)

**Sequencing:** Polish earns its keep after a feature-complete app. Session filter is most urgent (unwieldy at 20+ sessions) but cleaner after M5's list item model settles. Daemon mode opens path toward background alerting independent of an active TUI session.

**Status:** Complete. Remaining follow-up is documentation drift prevention and any manual UX tuning discovered during daily use.
